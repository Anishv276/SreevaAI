PROJECT: SreevaAI HR Interview Platform

================================================================================
ISSUE OVERVIEW
================================================================================

The codebase uses a soft-delete mechanism (isDeleted field) to mark deleted
records. A global Prisma middleware automatically filters out deleted records
in ORM queries, but RAW SQL queries bypass this middleware and must manually
add WHERE "isDeleted" = false filters.

FINDING: 7 API endpoints and 1 utility module use raw SQL queries WITHOUT
soft-delete filters, causing deleted organizations, drives, applications,
and interviews to be counted in statistics and displayed in dashboards.

THE PROBLEM PATTERN
================================================================================

❌ CURRENT (WRONG) — Deleted records included:

  SELECT COUNT(*)::INT FROM "Drive"

  SELECT o.name, COUNT(i.id) FROM "Organization" o
  JOIN "Drive" d ON d."orgId" = o.id
  JOIN "Application" a ON a."driveId" = d.id
  JOIN "Interview" i ON i."applicationId" = a.id

✅ CORRECT — Deleted records excluded:

  SELECT COUNT(*)::INT FROM "Drive"
  WHERE "isDeleted" = false

  SELECT o.name, COUNT(i.id) FROM "Organization" o
  JOIN "Drive" d ON d."orgId" = o.id
  JOIN "Application" a ON a."driveId" = d.id
  JOIN "Interview" i ON i."applicationId" = a.id
  WHERE o."isDeleted" = false
    AND d."isDeleted" = false
    AND a."isDeleted" = false
    AND i."isDeleted" = false

================================================================================
ROOT CAUSE
================================================================================

Prisma Middleware (lib/prisma.ts) auto-filters ORM operations:
  ✓ prisma.organization.findMany()
  ✓ prisma.organization.count()
  ✓ prisma.drive.findUnique()
  etc.

But DOES NOT filter raw SQL:
  ✗ prisma.$queryRaw("SELECT FROM Organization")
  ✗ prisma.$queryRawUnsafe(...)

Raw SQL queries account for ~40% of database access in stats/admin endpoints.
These queries were not updated when soft-delete was implemented.
